# Desktop App — Stats Section Design Spec

**Date:** 2026-05-25
**Purpose:** Add a Stats section to the Desktop Dashboard showing file count, total storage size, last sync time, and connection mode.

---

## 1. What's being added

A **Stats section** inserted between "Sync Folder" and "Recent Activity" on the existing Dashboard screen. Four metrics displayed in a two-column label/value layout, refreshing every 30 seconds.

---

## 2. UI Layout

```
┌─────────────────────────────────┐
│  PJDrive              [Logout]  │
├─────────────────────────────────┤
│  Sync Status                    │
│  ● Connected   user@email.com   │
├─────────────────────────────────┤

│  Last sync   2 min ago          │
│  Mode        SSE (real-time)    │
├─────────────────────────────────┤
│  Recent Activity                │
│  ─────────────────────────────  │
│  ↑ report.pdf     just now      │
│  ↓ notes.txt      2 min ago     │
└─────────────────────────────────┘
```

**Window height:** Dashboard grows from 500px → 580px.

**Loading state:** Stats show `—` on first load until the API responds.

**Error state:** If the API call fails, stats keep showing the last known values (no visual error — connection issues are already shown by the status dot).

---

## 3. Metrics

| Label | Value | Source |
|---|---|---|
| Files | `142` | `GET /stats` → `fileCount` |
| Total size | `1.4 GB` (human-readable) | `GET /stats` → `totalBytes` |
| Last sync | `2 min ago` (relative time) | `getLastSyncAt()` from sync state |
| Mode | `SSE (real-time)` or `Polling (fallback)` or `Offline` | `getSyncStatus().mode` |

**Size formatting:**
- `< 1 KB` → `0 KB`
- `>= 1 KB` → `X KB`
- `>= 1 MB` → `X.X MB`
- `>= 1 GB` → `X.X GB`

**Mode labels:**
- `'sse'` → `SSE (real-time)`
- `'poll'` → `Polling (fallback)`
- `'off'` → `Offline`

## 4. New API endpoint

```
GET /api/stats
Authorization: Bearer <token>

Response 200:
{
  "fileCount": 142,
  "totalBytes": 1503238553
}
```

SQL query:
```sql
SELECT COUNT(*) AS file_count, COALESCE(SUM(size_bytes), 0) AS total_bytes
FROM files
WHERE owner_id = :userId;
```

Route file: `apps/api/src/routes/stats.ts`
SQL file: `apps/api/src/routes/stats.sql`
Registered in: `apps/api/src/index.ts`

---

## 5. IPC changes

**New channel:** `stats:get`

Main process handler (in `apps/desktop/src/main/ipc.ts`):
- Calls `GET /stats` using stored token via axios
- Returns `{ fileCount, totalBytes, lastSyncAt, mode }`
- `lastSyncAt` comes from `getLastSyncAt()` (sync state)
- `mode` comes from `getSyncStatus().mode`

**Renderer** calls `window.api.stats.get()` on dashboard init and every 30s.

**Preload** exposes: `window.api.stats = { get: () => ipcRenderer.invoke('stats:get') }`

---

## 6. Refresh cadence

Stats refresh on the same 5-second status poll cycle — `refreshStats()` is called alongside `refreshStatus()` inside the existing `setInterval`. This avoids a separate timer and keeps things simple.

Actually: stats are cheaper to show stale since they change slowly. Refresh stats every **30 seconds** via a separate `setInterval`, independent of the 5s status poll.
